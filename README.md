# navio-developer-docs

Unified developer documentation for the [Navio](https://nav.io) blockchain. Published at **https://docs.nav.io/**.

Covers:

-   **Concepts** — BLSCT privacy model, outpoint model, consensus, networks, wallet formats.
-   **Node operator** — install, configure, stake, harden, monitor `naviod`.
-   **RPC reference** — every JSON-RPC command, with every BLSCT command auto-generated from `navio-core` source.
-   **BLSCT protocol deep dive** — curve, keys, outputs, detection, range proofs, signatures, tx/block format.
-   **SDK (`navio-sdk`)** — TypeScript SDK for wallets and transactions (with auto-generated TypeDoc reference).
-   **BLSCT library (`navio-blsct`)** — TS bindings for `libblsct`.
-   **Block explorer (`navio-blocks`)** — architecture, self-host, REST API reference.
-   **Guides** — end-to-end tutorials.
-   **Reference** — opcodes, error codes, network constants, glossary, changelog.

## Stack

-   **[MkDocs](https://www.mkdocs.org/)** with the **[Material](https://squidfunk.github.io/mkdocs-material/)** theme.
-   Versioning via **[mike](https://github.com/jimporter/mike)**.
-   Auto-generated API references via **[TypeDoc](https://typedoc.org/)** with the markdown plugin.
-   RPC reference generated from `navio-core` source by `scripts/extract-blsct-rpc.py`.
-   OpenAPI-to-Markdown via [widdershins](https://github.com/Mermade/widdershins) (or the bundled Python fallback).
-   Deployed to **GitHub Pages** at `docs.nav.io` by `.github/workflows/build-docs.yml` (nightly + on push).

## Local development

```bash
git clone https://github.com/nav-io/navio-developer-docs.git
cd navio-developer-docs

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# live preview
mkdocs serve

# one-off build
mkdocs build
```

Open `http://localhost:8000`.

## Regenerating auto-generated sections

Requires the upstream repos to be publicly accessible and `gh` CLI authenticated.

```bash
# BLSCT RPC from navio-core source
python3 scripts/extract-blsct-rpc.py /path/to/navio-core > docs/rpc/blsct.md

# Full pipeline
scripts/fetch-sdk-docs.sh            # navio-sdk TypeDoc → docs/sdk/api/
scripts/fetch-blsct-docs.sh          # navio-blsct TypeDoc → docs/blsct-lib/api/
scripts/fetch-core-rpc.sh            # BLSCT RPC + category help → docs/rpc/
scripts/fetch-explorer-api.sh        # OpenAPI → docs/explorer/api/
scripts/fetch-core-release.sh        # release notes → docs/reference/changelog.md
```

## Versioning

Tag a release, build, then publish with mike:

```bash
mike deploy --push --update-aliases 1.0 latest
mike set-default --push latest
```

## Contributing

Handwritten pages live under `docs/`. API and RPC reference subdirectories are regenerated by CI — do not hand-edit them (your changes will be overwritten). If you find a factual bug in auto-generated content, fix the source repo upstream and open an issue on this repo to trigger regeneration.

Open a PR; CI will build a preview artefact you can download.
